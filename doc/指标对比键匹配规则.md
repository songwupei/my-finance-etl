# 财务指标名称对比键匹配规则说明

## 背景

财务系统中，财务数据有两条指标命名路径：

- **标准指标名称**（`standard_path`）：来自 `dim_standard_account` 维度表，是按会计科目体系组织的标准化层级路径
- **原始指标名称**（`raw_path`）：来自原始采集数据，反映报表中实际的指标层级结构

两条路径的结构和层级起点不同，直接比较全路径无法正确匹配。因此改用**顶层科目匹配**策略：分别从两条路径中提取**顶层科目名**进行匹配判定。

---

## 核心算法

### 顶层科目匹配

以资产负债表 `03-3-1 其中：专项资金` 为例：

```
Step 1: 取行号 "03-3-1" → 取第一段 "03"
Step 2: 在同表 code 层级中向前找到 "03. 货币资金"
         → 顶层科目名称 = "货币资金"
Step 3: 用 "货币资金" + 报表类别 "资产负债表"
         在 standard_accounts.json 中查找
         → account_name = "货币资金"
Step 4: 原始路径由 ETL 层按 code 层级构造：
         "货币资金 > 商业银行存款 > 专项资金"
Step 5: 对比：
         标准对比键 = "货币资金"
         原始对比键 = "货币资金"
         是否匹配 = True
```

### 关键问题：Excel 中存在多个 "03"

所有指标位于**同一工作表** `司库报表_主要财务指标快报表`，通过章节标题作为命名空间：

```
一、资产负债表指标        ← 命名空间起点（以下归为 资产负债表）
01.资产总额
02.  流动资产合计
03.    货币资金
...
61.所有者权益合计
二、利润表指标            ← 切换命名空间（以下归为 利润表）
01.营业收入
...
07.财务费用
...
四、现金流量表指标        ← 切换命名空间（以下归为 现金流量表）
01.经营活动产生的现金流量
...
```

| 命名空间章节 | 对应报表类型 | code "03" 的意义 |
|-------------|-------------|-----------------|
| `一、资产负债表指标` | 资产负债表 | `03. 货币资金` |
| `二、利润表指标` | 利润表 | `03. 营业利润` |
| `四、现金流量表指标` | 现金流量表 | `03. 筹资活动产生的现金流量` |

> **重要**：Excel code 与 `standard_accounts.json` code 是两套独立的编号体系！
> - Excel 的 `03` = "货币资金"（资产负债表）
> - 标准库的 `03` = "所有者权益合计"（资产负债表）
>
> 因此查找时**不能通过 code 匹配标准库**，必须通过**名称**查找。

## 提取规则

### 1. 标准对比键

取自 `sa.account_name`（`dim_standard_account.account_name`），即 ETL 层匹配到的标准科目名称。

- 当 ETL 匹配粒度为**顶层科目**时，`account_name` 即为顶层科目名（如"货币资金"、"应收账款"）
- 无需从 `standard_path` 做任何截断或提取

### 2. 原始对比键

取自 `raw_path` 的第一段（顶层科目名）：

```
原始指标名称 = "货币资金 > 商业银行存款 > 专项资金"
原始对比键   = "货币资金"    ← 取第一段
```

### 3. 是否匹配

两个对比键直接做字符串等值比较：

```
是否匹配 = (标准对比键 == 原始对比键)
```

---

## ETL 层处理流程

### 1. 章节检测（Parser）

在 `parse_report_sheet()` 中，按行顺序扫描，检测章节标题：

- 正则匹配 `^([一二三四])、(?:.*?)指标`
- 匹配到章节标题时：
  - 设置当前命名空间（`current_report_category`）
  - 重置 `namespace_code_map`（新命名空间下的 code 互不干扰）
  - 跳过该行（章节标题本身不是数据指标）

### 2. 命名空间隔离

每个命名空间内构建独立的 `code → clean_name` 映射表：

```
namespace_code_map = {}  // 每个命名空间开始时重置

处理 "03. 货币资金" (level=1):
  → namespace_code_map["03"] = "货币资金"

处理 "03-3. 商业银行存款" (level=2):
  → top_code = "03" → namespace_code_map["03"] = "货币资金"
  → top_level_name = "货币资金"

处理 "03-3-1 其中：专项资金" (level=3):
  → top_code = "03" → top_level_name = "货币资金"
```

### 3. 原始路径构造

沿用 parser 现有的 `path_stack` 算法。`clean_name` 已去除"其中："等前缀，路径自动构建为：

```
货币资金 > 商业银行存款 > 专项资金
```

### 4. 标准科目匹配（Matcher）

新增**顶层科目名称匹配**策略，优先于原有策略执行：

1. 取 `top_level_account_name`（如"货币资金"）
2. 在索引中按名称查找匹配的科目
3. 如果多个科目同名，用 `report_category` 消歧
4. 匹配成功则返回顶层科目节点，`account_code` 为顶层科目 code

### 5. 事实表写入

新增 `top_level_account_name` 字段，直接从 parser 写入事实表。

## Flask API 输出

`GET /api/node_data` 接口在每条记录中新增/修改以下字段：

| 字段 | 来源 | 说明 |
|------|------|------|
| `指标名称` | `sa.account_name` | 标准科目名称（顶层） |
| `标准对比键` | `sa.account_name` | 直接取标准科目名 |
| `原始对比键` | `raw_path` 第一段 | 从原始路径提取顶层科目名 |
| `是否匹配` | 两者比较 | 等值比较 |

不再使用 `_suffix_dedup()`、`extract_standard_compare_key()`、`extract_raw_compare_key()`。

## 完整示例

### 示例数据

| 字段 | 值 |
|------|----|
| 报表类别 | 资产负债表 |
| 行号 | `03-3-1 其中：专项资金` |
| 标准指标名称 | `资产总额 > 流动资产合计 > 应收账款 > 集团外应收账款` |
| 原始指标名称 | `货币资金 > 商业银行存款 > 专项资金` |

### 处理步骤

**ETL 层：**

1. 检测到章节标题 `一、资产负债表指标` → 设置命名空间为"资产负债表"
2. 扫描到 `03. 货币资金` (level=1) → `namespace_code_map["03"] = "货币资金"`
3. 扫描到 `03-3. 商业银行存款` (level=2) → 顶层科目 = "货币资金"
4. 扫描到 `03-3-1 其中：专项资金` (level=3) → 顶层科目 = "货币资金"
5. 构造原始路径：`货币资金 > 商业银行存款 > 专项资金`
6. 匹配标准库：`top_level_account_name = "货币资金"` → 匹配到 `account_code = "01.03"` 的 "货币资金" 科目
7. 写入事实表：`account_code = "01.03"`, `top_level_account_name = "货币资金"`

**Flask 层：**

| 字段 | 值 |
|------|----|
| 指标名称 | `货币资金` （来自 `sa.account_name`） |
| 标准对比键 | `货币资金` |
| 原始对比键 | `货币资金`（`raw_path` 第一段） |
| 是否匹配 | ✅ 是 |

### 不匹配示例

| 字段 | 值 |
|------|----|
| 指标名称 | `短期借款` |
| 原始对比键 | `货币资金` |
| 是否匹配 | ❌ 否 |

---

## 实现位置

- **章节检测 + 命名空间跟踪**：`parser.py` `parse_report_sheet()` 方法
- **顶层科目匹配**：`matcher.py` `match()` 方法，策略 0
- **事实表存储**：`data_warehouse.py` `build_fact_table()`，`top_level_account_name` 字段
- **对比键输出**：`flask_app.py` `get_node_data()`，直接对比 `sa.account_name` 与 `raw_path` 第一段
